## 数据真值与降级边界

- 市场数据真值是 NAS 上由 published manifest 明确引用的不可变 Parquet；本机
  DuckDB 只保存刷新审计、调度状态和 published pointer 等控制信息。
- 持仓、自选、策略定义、预警和私有备份保留在 Mac 本机 SQLite，不写入市场数据集。
- AKShare 补充数据集已独立初始化；真实 canary 因上游不可用未发布数据，manifest
  为空。它不阻断 BaoStock OHLCV 核心链路，也不能用空值或 OHLCV 推断资金流。
- NAS 断开、日历冲突、覆盖不完整或缺复权因子时 fail closed：保留上一完整发布，
  不把 partial 数据混入市场、估值、策略或预警结论。

## 五阶段完成验收顺序

1. 等待当前历史回填结束，从 NAS manifest 读回实际 published 日期、总行数、文件
   hash、覆盖和容量；不得仅按进程日志或计划数量宣布完成。
2. 在没有刷新锁占用且至少具备 21 个有效交易日后运行只读真实验收：

   ```bash
   uv run python -m backend.app.acceptance \
     --nas-root /Volumes/Stock/stock-eva-market
   ```

   验收使用自动销毁的临时用户 SQLite，不读取或修改真实持仓。策略输出统一称为
   “规则候选”，不构成投资建议。
3. 验收通过后安装并加载 5 个用户级 LaunchAgent，读回 API、Web、日终刷新、日历
   同步和私有库备份状态；确认不会与手动作业重复运行。
4. 打开工作台做最终浏览器验收：数据截止日、覆盖、持仓估值、策略候选和预警状态
   必须与后端及 manifest 一致，控制台无错误，移动端无横向溢出。
5. 运行全量测试、格式检查、敏感信息与 Git 差异检查，再提交并推送最终验收结果。
