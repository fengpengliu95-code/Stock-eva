## 数据真值与降级边界

- NAS 上由 published manifest 引用的不可变 Parquet 是历史归档真值；交互式安装
  完整验证后原子同步到 `Application Support` 本机镜像，macOS 后台只读取该镜像。
- 本机 DuckDB 只保存刷新审计、调度状态和 published pointer 等控制信息；每日新增
  行情以相同 manifest 语义发布到本机镜像。
- 持仓、自选、策略定义、预警和私有备份保留在 Mac 本机 SQLite，不写入市场数据集。
- AKShare 补充数据集已独立初始化；真实 canary 因上游不可用未发布数据，manifest
  为空。它不阻断 BaoStock OHLCV 核心链路，也不能用空值或 OHLCV 推断资金流。
- TCC 已确认会拒绝 LaunchAgent 直接访问 `/Volumes/Stock`；后台运行不申请扩大权限，
  也不在本机镜像失效时静默回退 NAS。
- 本机镜像缺失、日历冲突、覆盖不完整或缺复权因子时 fail closed：保留上一完整发布，
  不把 partial 数据混入市场、估值、策略或预警结论。

## 五阶段完成验收顺序

1. NAS 历史回填已完成并读回：260 个交易日、829,494 行、约 38 MB，最新
   2026-07-24。
2. 在没有刷新锁占用时运行只读真实验收：

   ```bash
   uv run python -m backend.app.acceptance \
     --nas-root /Volumes/Stock/stock-eva-market
   ```

   验收使用自动销毁的临时用户 SQLite，不读取或修改真实持仓。策略输出统一称为
   “规则候选”，不构成投资建议。
3. 通过交互式安装器验证 NAS 归档并原子建立本机镜像，再安装 5 个用户级
   LaunchAgent。已安装 plist 不得包含 `Documents` 或 `/Volumes/Stock` 运行路径。
   读回 API、Web、日终刷新、日历同步和私有库备份状态。
4. 打开工作台做最终浏览器验收：数据截止日、覆盖、持仓估值、策略候选和预警状态
   必须与后端及 manifest 一致，控制台无错误，移动端无横向溢出。
5. 运行全量测试、格式检查、敏感信息与 Git 差异检查，再由主任务提交并推送最终验收
   结果。在上述读回完成前，部署状态保持“待最终验证”。
